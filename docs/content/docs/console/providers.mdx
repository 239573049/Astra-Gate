---
title: 提供商
description: 添加上游服务商、配置密钥与计费、测试连接
---

提供商（Provider）是 Astra 的上游入口：一个接口地址 + 一种协议 + 一份凭据。可以同时添加多个——比如同一个 DeepSeek 账号建两个条目用不同倍率，或官方 API 与 OpenRouter 并存。

## 提供商列表

<Screenshot src="/screenshots/providers.png" alt="提供商列表：每行一个提供商，右侧开关与箭头" title="Astra — 提供商" caption="提供商列表；行内显示协议、模型数与价格表" />

每行从左到右：

- **图标与名称** — 点击进入详情；
- **徽标** — 绑定的客户端（绿色，如「Codex」），「未设置密钥」（橙色）提醒补 Key，「模板更新」表示模板有新版本；
- **详情行** — 协议 · 模型数 · 价格表 · 倍率（非 1.0 时显示）；
- **开关** — 临时停用某个提供商（停用后请求不再路由到它）。

## 添加提供商

点右上角 **添加提供商**，弹出两步向导：

<Screenshot src="/screenshots/provider-add.png" alt="添加提供商：选择模板步骤，含分类筛选与模板卡片" title="Astra — 添加提供商" caption="第一步：选择模板（支持搜索与分类筛选）" />

1. **选择模板** — 模板自带接口地址、协议与默认模型列表。分类：官方 / 订阅 / 国内 / 聚合平台 / 本地。没有匹配的就选「自定义提供商」，手填任意 OpenAI / Anthropic / Gemini 兼容接口；
2. **填写信息** — 名称、接口地址（通常以 `/v1` 结尾）、协议、认证方式与 API Key。

<Callout type="info" title="订阅账号（OAuth）">
  部分模板支持「订阅登录」而无需 API Key：创建提供商后在其 **设置 → 订阅账号** 点「登录订阅」，
  按官方授权流程在浏览器完成登录，令牌加密保存在本机、即将过期时自动刷新。配额以官方条款为准。
</Callout>

## 从其他应用导入

已经在别的工具里配置过中转或官方 Key？点右上角 **从其他应用导入**，Astra 会只读扫描本机以下位置并列出可导入的提供商：

| 来源 | 读取位置 |
| --- | --- |
| CC Switch | `~/.cc-switch/cc-switch.db`（旧版为 `config.json`） |
| Alma | 系统用户配置目录下 `alma/chat_threads.db` |
| Claude Code | `~/.claude/settings.json`（遵循 `CLAUDE_CONFIG_DIR`） |
| Codex | `~/.codex/config.toml`（遵循 `CODEX_HOME`，只读自定义 `[model_providers.*]` 且带内联 token 的条目） |
| Magpie | `~/.config/magpie/providers.json` |

- 列表里每一行显示名称、协议与地址、遮掩后的 Key、模型数和状态：**新增**（默认勾选）、**已存在**（同地址同 Key，不可选）、**同地址**（地址相同但 Key 不同，可选并作为新提供商导入）、**已停用**（来源里已关闭，默认不勾选）、**无法导入**（附原因）；
- 只读、不修改来源；API Key 由服务端直接读取并加密保存，**不经过浏览器**，预览里也只有遮掩值；
- 同一来源里 Key 与主机都相同的多条配置会合并成一个提供商的多个端点；Magpie 里一个提供商的多个 Key 会各导入成一个提供商；
- 官方登录（Claude / ChatGPT / Copilot 等订阅登录）、路由、限流、余额、会话与用量不会导入；导入不会绑定或改动任何客户端配置，也不会发起上游请求——导入后可用「测试连接」确认。

<Callout type="info" title="Claude Code 已被 Astra 接管时">
  此时 `settings.json` 里的地址和令牌是 Astra 自己写入的，导入会改为读取接管前记录的原值，不会把 Astra 导入回自己。
</Callout>

## 提供商详情

<Screenshot src="/screenshots/provider-detail.png" alt="提供商详情：设置标签页，含基本信息、认证、计费分区" title="Astra — DeepSeek" caption="详情页「设置」标签；右上角可测试连接" />

详情页有两个标签：

### 模型

该提供商暴露的模型列表。可以从上游拉取（**从上游获取**），也可以手动输入模型 ID。每个模型可单独覆盖参数与价格（覆盖后显示「已覆盖」，可一键重置为继承）。

### 设置

按分区组织：

| 分区 | 内容 |
| --- | --- |
| **基本信息** | 名称、区域/版本、协议（OpenAI Chat / OpenAI Responses / Anthropic / Gemini） |
| **认证** | API Key（加密存储，留空不修改；只显示掩码）、认证方式（Bearer / x-api-key / x-goog-api-key / query-key） |
| **接口** | 每种协议一个地址；客户端协议与上游不同时 Astra 自动转换，转换时按「上游协议优先级」选择接口 |
| **计费** | **价格表**（决定用哪套模型价格，如 `deepseek`、`openrouter`）与 **价格倍率**（中转站按官方价 ×1.1 计费的场景） |
| **用量查询** | 查询余额或套餐用量（见下文「用量查询」）；订阅类提供商在账号区查看额度，没有这一分区 |
| **高级** | 仅此提供商生效的 HTTP 代理、额外请求头、适配器设置（JSON） |

## 用量查询

API Key 类提供商可以在 **设置 → 用量查询** 里打开余额 / 套餐用量查询（参考 cc-switch 的同名功能）。打开后，结果显示在提供商卡片底部和托盘的「额度与余额」里，并按间隔在后台刷新。

- **默认关闭**：同一个地址可能同时有余额接口和套餐接口，Astra 不替你猜，需要手动启用。
- **凭据**：默认用提供商自己的 API Key 和认证方式（Bearer / x-api-key / query-key 等）发请求，不需要再填一遍。
- **失败只显示，不影响使用**：查询失败（Key 无查询权限、限流、超时……）只在卡片上显示错误，并保留上一次成功的结果；提供商照常可用。
- **自动查询间隔**：全局默认 30 分钟（**设置 → 通用 → 提供商用量查询**，0 = 关闭），单个提供商可以单独设置；连续失败 3 次后间隔自动放大到 4 倍，成功一次即恢复。

内置模板（根据提供商模板或接口域名自动选中，也可以手动换）：

| 模板 | 类型 | 请求 |
| --- | --- | --- |
| DeepSeek | 余额 | `GET {origin}/user/balance` |
| OpenRouter | 余额 | `GET {origin}/api/v1/credits` |
| SiliconFlow | 余额 | `GET {origin}/v1/user/info`（`.cn` 按人民币，`.com` 按美元） |
| StepFun | 余额 | `GET {origin}/v1/accounts` |
| Novita AI | 余额 | `GET {origin}/v3/user/balance` |
| New API / One API | 余额 | `GET {origin}/api/user/self`，需要填 **用户 ID** 和 **系统访问令牌**（个人设置里生成，不是 `sk-` 开头的 API Key；令牌加密保存，界面只显示「已保存」） |
| Kimi For Coding | 套餐用量 | `GET https://api.kimi.com/coding/v1/usages` |
| GLM Coding Plan | 套餐用量 | `GET {origin}/api/monitor/usage/quota/limit`（open.bigmodel.cn / api.z.ai） |
| MiniMax Coding Plan | 套餐用量 | `GET {origin}/v1/api/openplatform/coding_plan/remains` |

`{origin}` 是提供商接口地址的协议 + 域名（例如 `https://api.deepseek.com`）。火山方舟的用量接口需要火山引擎 AK/SK 签名，暂不提供内置模板。

### 自定义查询

模板选「自定义」后，填写请求（方法、URL、认证方式、请求头）和**提取规则**。和 cc-switch 用 JavaScript 写提取函数不同，Astra 的提取规则是声明式 JSON：

```json
{
  "isValid": "success",
  "invalidMessage": "message",
  "planLabel": "data.group",
  "unit": { "$const": "USD" },
  "remaining": { "$div": ["data.quota", 500000] },
  "used": { "$div": ["data.used_quota", 500000] },
  "total": { "$div": [{ "$add": ["data.quota", "data.used_quota"] }, 500000] }
}
```

- 字符串是响应里的**路径**（`data.balance`、`items[0].total`），数字是常量；字符串常量要写成 `{ "$const": "USD" }`。
- 数组表示候选：按顺序取第一个存在的值（相当于 `a || b`）。
- 运算：`$add`、`$sub`、`$mul`、`$div`、`$scale`（配 `by`）、`$pctUsed`（`{used, total}` → 已用百分比）、`$eq`、`$not`、`$case`（`{on, cases, default}`）、`$var`（`host`、`origin`、`baseUrl` 等变量）、`$time`（秒 / 毫秒时间戳或日期字符串）。
- 字段与 cc-switch 提取器的返回值一一对应：`isValid`、`invalidMessage`、`remaining`、`total`、`used`、`unit`、`planName`、`extra`；多个套餐 / 窗口用 `plans` 数组，每项可以用 `each` 遍历数组、`where` 过滤、`first` 只取第一个、`when` 条件显示，另有 `usedPercent`、`resetsAt`、`windowMinutes`。
- 取不到的字段就是空的，**绝不会被当成 0**。
- URL 和请求头里可以用占位符 `{{origin}}`、`{{baseUrl}}`、`{{host}}`、`{{apiKey}}`，以及 `{{userId}}`、`{{accessToken}}`（在表单里填写，令牌加密保存）。

**测试查询** 用当前未保存的配置发一次真实请求，显示请求地址、HTTP 状态、提取结果和**已脱敏的原始响应**（其中的 Key 与令牌会被替换成 `••••`），方便对照响应结构写提取规则。

## 测试连接

右上角 **测试连接** 会打开测试弹窗，用当前配置向上游发**真实请求**——这是排查 Key、地址与额度问题最快的办法。

- **单模型**：左侧选择测试模型（可选列表外的任意模型 ID）、测试协议（仅该提供商已配置的端点协议）、是否流式、最大输出 tokens 与提示词；右侧实时显示 **HTTP 响应 / 首字等待 / 首字总延迟 / 完整耗时** 四项指标，以及提供商回复的 **预览**（流式边生成边显示）与 **原文**（网关处理后的响应正文，凭据已脱敏，可复制）。
- **批量模型**：勾选多个模型（最多 3 个并发测试），表格逐行显示状态与耗时；「停止后续」取消尚未开始的模型，进行中的请求跑完；点「查看」可看单个模型的详细结果。

<Callout type="warn" title="测试会消耗额度">
  每次测试都是一条真实请求：会应用隐私护栏、写入请求日志并计入用量与费用，且失败不会自动重试。需要多次尝试时请留意额度。
</Callout>

<Callout type="warn" title="删除提供商前">
  如果还有客户端绑定在这个提供商上，Astra 会拒绝删除并提示先为它们切换提供商，避免客户端突然失联。
</Callout>
