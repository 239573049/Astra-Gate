「接管」是 Astra 的核心体验：不用手工编辑客户端配置文件，控制台里点一下即可把客户端指向网关，随时可还原。

## 每个客户端一个标签页

<Screenshot src="/screenshots/clients.png" alt="客户端页：顶部是客户端标签，下方是 Codex 的接管卡片" title="Astra — 客户端" caption="客户端页：Codex 已启用并绑定 DeepSeek" />

页面顶部是本机检测到的客户端标签（启用过的带 ✓）。选中某个客户端后，下方是它的接管卡片：

- **状态行** — 「已启用」徽标 + 已写入的配置文件路径；右侧 **禁用并还原**；下方是最近一次写入配置的时间；
- **使用的提供商** — 单选卡片，切换后**立即生效**，不需要修改客户端配置文件；
- **令牌** — 写入客户端配置的[令牌](/docs/console/tokens)，默认是「默认令牌」，多个客户端可以共用一个；
- **模型** — 启用时写入客户端配置的默认模型。Claude Code 还提供 Opus / Sonnet / Haiku 三档选择，对应 `ANTHROPIC_DEFAULT_OPUS_MODEL` / `ANTHROPIC_DEFAULT_SONNET_MODEL` / `ANTHROPIC_DEFAULT_HAIKU_MODEL`（Haiku 档兼作快速/后台模型）。所有模型选项默认留空，留空就不写入，配置文件里已有的同名设置也不会被改动；修改后需要重新写入客户端配置；
- **维护** — 复制配置文件路径、配置备份。

支持的客户端：Codex、Claude Code、Gemini CLI、OpenCode、Claude Desktop、Grok Build、Pi、Hermes Agent、MiniMax Code、GitHub Copilot CLI、VS Code 中的 GitHub Copilot，以及 Crush、Qwen Code、Droid、Kimi Code、Zed、VS Code Insiders、VSCodium、omp（oh-my-pi）、MiMo Code、DeepSeek Harness、WorkBuddy、Muse Code、NextCoWork。

后加入的几个客户端由 Astra 写入这些位置（括号内为可覆盖目录的环境变量）：

| 客户端 | 配置文件 | Astra 写入的内容 |
| --- | --- | --- |
| **Pi** | `~/.pi/agent/models.json`、`settings.json`（`PI_CODING_AGENT_DIR`） | 新增 `astra` 提供商（含所绑定提供商的模型列表）；选了模型时设置 `defaultProvider` / `defaultModel` |
| **Hermes Agent** | `~/.hermes/config.yaml`（`HERMES_HOME`；Windows 为 `%LOCALAPPDATA%\hermes`） | `model` 段：`provider: custom`、`base_url`、`api_key`，选了模型时写 `default` |
| **MiniMax Code** | `~/.minimax/config.yaml`（`MINIMAX_DATA_DIR`） | 新增 `custom_provider.astra`（含模型列表）；选了模型时设置 `defaultModel` |
| **Copilot CLI** | `~/.copilot/providers.json`、`settings.json`（`COPILOT_HOME`） | 在 BYOK 列表里新增 `astra` 提供商及其模型（不动你已有的条目）；选了模型时设置 `model` 为 `astra/<模型>` |
| **VS Code Copilot** | VS Code 用户目录下的 `chatLanguageModels.json`（macOS `~/Library/Application Support/Code/User`，Windows `%APPDATA%\Code\User`，Linux `~/.config/Code/User`） | 新增名为 `Astra` 的 Custom Endpoint 模型组（Chat Completions），列出所绑定提供商的模型；令牌写在每个模型的 `requestHeaders` 里。模型在 VS Code 的模型选择器中挑选 |
| **Crush** | `~/.config/crush/crush.json`（`CRUSH_GLOBAL_CONFIG` 为目录；也认 `XDG_CONFIG_HOME`） | 新增 `providers.astra`（`openai-compat`，含模型列表）；选了模型时设置 `models.large`。若同目录有 `crushrc`，它对同名顶层键优先于 `crush.json`，卡片会提示 |
| **Qwen Code** | `~/.qwen/settings.json` | 在 `modelProviders.openai` 数组里新增 Astra 的模型条目，令牌写入 `env.ASTRA_QWEN_API_KEY`；选了模型时设置 `security.auth.selectedType` 与 `model.name`。模型列表热加载，切换模型可能需要重启 |
| **Droid** | `~/.factory/settings.json` | 在 `customModels` 里为每个模型新增一条 BYOK 条目（`generic-chat-completion-api`，显示名 `Astra: <模型>`）。Droid 不公开自定义模型的默认 id，所以 Astra 不设默认模型，请在 `/model` 里挑选 |
| **Kimi Code** | `~/.kimi-code/config.toml`（`KIMI_CODE_HOME`） | 新增 `[providers.astra]`（`type = "openai"`）与每个模型一张 `[models.astra-<模型>]` 表（模型 id 里的 `.` 等符号在别名中换成 `-`）；选了模型时设置 `default_model`。旧版 Python Kimi CLI 的 `~/.kimi` 不会被改动 |
| **Zed** | `~/.config/zed/settings.json`（Windows `%APPDATA%\Zed`，Linux 认 `XDG_CONFIG_HOME`） | 新增 `language_models.openai_compatible.astra`（含模型列表）；选了模型时设置 `agent.default_model`。**Zed 不从 settings.json 读取密钥**，所以令牌不会被写入：请在 Zed 的智能体设置里选 Astra 提供商，把[令牌页](/docs/console/tokens)的令牌粘贴一次（或启动 Zed 前设置环境变量 `ASTRA_API_KEY`） |
| **VS Code Insiders / VSCodium** | 各自用户目录下的 `chatLanguageModels.json`（`Code - Insiders/User`、`VSCodium/User`），写法与 VS Code Copilot 相同 | VSCodium 默认不带 Copilot（Copilot Chat 也不在 Open VSX 上）：需要 `"chat.disableAIFeatures": false`、自定义 `product.json` 并手动安装 Copilot Chat 扩展，Astra 只写端点文件，卡片会提示 |
| **omp（oh-my-pi）** | `~/.omp/agent/models.yml`、`config.yml`（`PI_CODING_AGENT_DIR`） | 新增 `providers.astra`（`openai-completions`，含模型列表）；选了模型时设置 `modelRoles.default` 为 `astra/<模型>` |
| **MiMo Code** | `~/.config/mimocode/mimocode.json(c)`（Windows `%LOCALAPPDATA%\mimocode`） | 与 OpenCode 相同的 `provider.astra`；选了模型时设置 `model`。该客户端的 `MIMOCODE_HOME` 对路径的影响没有文档，设置了会提示 |
| **DeepSeek Harness** | `~/.dsh/profiles/desktop/cordis.patch.yml`、`~/.dsh/profiles/web/cordis.patch.yml`（取其中已存在的；`DSH_HOME`）和 `~/.dsh/.env` | 在 `llm-pi-ai` 行里新增 `providers.astra`（自定义模型 API，`openai-completions`，含模型列表），保留你已有的提供商；选了模型时把 `agent-default-model` 行的 `provider` / `model` 改为 Astra（其 `reasoningEffort` 暂时移除，自定义模型没有声明档位，停用时还原）。Harness 的配置里不放明文密钥，只放 `apiKeyEnv` 引用，所以令牌写进 `~/.dsh/.env` 的 `ASTRA_GATEWAY_API_KEY`（优先级最低，不会盖过你在 Harness 里保存的密钥或启动环境里的变量）。Harness 还没创建过 desktop / web 配置时请先启动一次；`$DSH_HOME/cordis.patch.yml`（家目录层）里若也有 `llm-pi-ai` 行，它会盖过 profile 里的，卡片会提示 |
| **Muse Code** | 用户的 shell 配置文件 `~/.zshrc`（只存在 `~/.bashrc` 时用它）；检测目录为 `~/.config/muse`。Muse 没有可写入的端点配置项 | 在 rc 文件里写入一段 `# >>> astra muse-code >>>` 受管块，定义 `muse` shell 函数：`muse exec` 与无子命令的交互式 `muse` 会带上 `--base-url <网关>/v1`、`META_API_KEY`（本客户端的网关令牌）和 `MUSE_MODEL` 运行，仅限这一次调用；`resume`、`login` 等其它子命令照常使用你的 Meta 账号。`MUSE_MODEL` 取你选的模型，未选时取绑定提供商的第一个模型（Muse 不带 `--model` 时的默认模型解析会报 "no visible models"）。需要重新打开终端。模型列表由网关的 `/muse-code/models`（主机根路径，不在 `/v1` 下）提供 |
| **WorkBuddy** | `~/.workbuddy/models.json` | 在 `models` 数组里为每个模型新增一条自定义模型（Chat Completions，`url` 为完整的 `/v1/chat/completions` 地址，显示名 `Astra: <模型>`），不动你已有的条目。WorkBuddy 会读取这里配置的模型并可在「设置 → 模型」里查看；文件热加载。0.3.0 及更早的 Astra 误写入 CodeBuddy 的 `~/.codebuddy/models.json`，重新「应用」后会把那里的 Astra 条目清掉。Astra 不设默认模型，请在模型选择器的自定义模型分组里挑选。若你设置了 `availableModels`，需把 Astra 的模型 id 加进去才会显示 |

Pi、MiniMax Code、Copilot CLI、VS Code 系列、Crush、Qwen Code、Droid、Kimi Code、Zed、omp、MiMo Code、DeepSeek Harness、WorkBuddy、NextCoWork 与 OpenCode 一样会列出所绑定提供商的模型，提供商的模型增减后会自动同步到客户端配置。

### 安装与更新

npm 分发的客户端（Codex、Claude Code、Gemini CLI、OpenCode、Grok Build、Pi、MiniMax Code、Copilot CLI、Crush、Qwen Code、Droid、Kimi Code、MiMo Code）可以在客户端页直接安装、检查并更新（`npm install -g <包>@latest`）。Hermes Agent 用它官方的安装脚本安装（macOS / Linux 为 `curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash`，Windows 为 `install.ps1`；Astra 会以 `--non-interactive` / `-NonInteractive` 运行，不弹交互），更新走它自带的 `hermes update`，最新版本来自 GitHub Releases。Zed、VS Code Insiders、VSCodium、omp（运行在 Bun 上）、DeepSeek Harness（桌面应用或 `npx @deepseek-ai/dsh web`）、WorkBuddy（桌面应用）和 Claude Desktop 一样只显示已安装版本和下载主页，Astra 不会替你运行安装命令。Qwen Code 需要 Node 22 及以上，Kimi Code 需要 Node 22.19 及以上；Node 太旧时 npm 会给出警告或客户端无法运行。`kimi` 命令也可能指向已归档的 Python 版 Kimi CLI，版本以 `kimi --version` 的输出为准。

## 启用

<Screenshot src="/screenshots/client-detail.png" alt="未启用的客户端标签页，展示启用按钮" title="Astra — 客户端" caption="未启用的客户端：点「启用…」由 Astra 代写配置" />

切换到一个未启用的客户端标签，点 **启用…**，Astra 会：

1. 展示将要写入的改动清单（只新增 / 修改 Astra 自己的配置项）；
2. **首次修改前备份原文件**（这份备份永久保留）；
3. 写入网关地址与所选令牌。

写入客户端的密钥形如 `sk-astra-xxxx.codex`：前半是令牌本身，`.` 后面是客户端标识，网关据此识别是哪个客户端发来的请求，再按该客户端绑定的提供商转发。用量记在令牌名下。

启用后客户端需要重启一次使配置生效；之后切换提供商、模型都在控制台完成，客户端无需再动。更换令牌需要重新写入配置：在「令牌」分区选择新令牌后点 **应用**，确认改动即可。

## 维护

| 项 | 说明 |
| --- | --- |
| **复制配置文件路径** | 快速定位 Astra 代管的客户端配置文件 |
| **配置备份** | 每次修改前自动备份，可随时恢复；首次修改前的备份永久保留，另有约 20 份滚动备份 |

需要让密钥失效时，到[令牌页](/docs/console/tokens)**重置**对应令牌：使用它的已启用客户端会自动改写配置。

<Callout type="info" title="Claude Desktop 与角色映射">
  Claude Desktop 只认 Sonnet / Opus / Haiku 这类「角色模型」。Astra 会把它们映射到你选择的提供商模型
  （该客户端标签页里的「角色映射」分区），至少设置一个角色，未设置的角色沿用第一个已设置的。
</Callout>

## 禁用与还原

- **禁用并还原** — 撤销 Astra 写入的配置项，恢复到启用前的状态；
- 如果某些配置项在你启用后又被手动改过（「漂移」），Astra 不会擅自覆盖，会列出这些项并询问是否**强制还原**；
- 服务器已经卸载、控制台打不开？终端运行 `astra restore-all` 可以**离线**还原全部客户端配置（见 [CLI 参考](/docs/cli/clients)）。

<Callout type="warn" title="密钥安全">
  Astra 写入客户端的是**令牌**（不是上游 API Key）。它只对本机网关有效，
  可随时在「令牌」页重置，使旧值立即失效。
</Callout>

<Callout type="info" title="从旧版本升级">
  旧版本给每个客户端各写一把 `astra-<客户端>-…` 本地密钥。升级后这些密钥立即失效，
  Astra 会在启动时自动把已启用客户端改写为「默认令牌」；手动改过配置（漂移）的客户端会被跳过，
  请在本页重新启用它们。
</Callout>
