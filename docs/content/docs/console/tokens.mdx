---
title: 令牌
description: 客户端与直接调用共用的访问凭据，以及按令牌统计的用量
---

令牌是访问 Astra 网关的凭据。客户端（Codex、Claude Code……）和你自己的脚本都靠令牌访问网关，每次请求的用量都记在对应令牌名下。

首次启动时 Astra 会自动生成一个**默认令牌**，启用客户端时默认写入它。需要区分用量（例如工作电脑和个人脚本）时，再新建几个令牌即可。

## 令牌卡片

每个令牌一张卡片，从上到下依次是：

- **名称与状态** — 默认令牌带「默认」徽标，停用的令牌带「已停用」徽标；
- **令牌** — 只显示前缀（如 `sk-astra-AbC123…`），点旁边的复制按钮才会取出完整令牌并写入剪贴板；
- **使用的客户端** — 当前写入了这个令牌、且已启用的客户端；
- **直连提供商** — 直接使用这个令牌调用时请求发往的提供商（见下文）；
- **最近使用** — 最后一次有请求使用它的时间；
- **今日 / 累计** 两组统计。

## 统计口径

| 指标 | 含义 |
| --- | --- |
| **今日消耗** | 今天（按 Astra 服务所在机器的本地日期）使用该令牌的请求费用合计，副文本为请求数 |
| **今日 Token** | 今天的输入 + 输出 token，副文本分别列出输入与输出 |
| **缓存命中率** | 缓存命中（cache read）token ÷ 输入 token；输入为 0 时显示「—」 |
| **TPS** | 加权输出速度：成功且同时测得生成耗时与输出 token 的请求，其输出 token 总量 ÷ 生成耗时总和（秒），比逐条平均更不受个别短请求影响 |
| **累计消耗 / 累计 Token / 累计请求** | 令牌从创建起的总量 |

<Callout type="info" title="累计统计不受日志保留期影响">
  「今日」统计来自请求日志；「累计」统计是独立保存的计数器，随每条请求一起累加。
  即使在设置里开启了请求日志保留天数、旧日志被清理，累计数也不会减少。
  从旧版本升级时，已有的请求日志全部计入默认令牌。
</Callout>

请求日志页可以按令牌筛选，并显示每条请求使用的令牌；概览页也可以按令牌筛选，「令牌」标签页按令牌汇总费用与用量。

## 客户端如何使用令牌

在[客户端页](/docs/console/clients)启用客户端时，Astra 把 `令牌.客户端标识`（例如 `sk-astra-AbC…xyz.codex`）写进客户端配置。网关按 `.` 后面的标识识别客户端，再按该客户端绑定的提供商转发。多个客户端可以共用同一个令牌，各自的提供商互不影响。

## 直接调用

不经过客户端、直接在 curl、脚本或其他工具里使用**完整令牌**（不带 `.客户端` 后缀）也可以：

1. 点卡片上的 **设置**，选择 **直连提供商**（订阅类提供商还可以选择具体账号）；
2. 复制令牌，把工具的 base URL 指向 `http://127.0.0.1:<端口>/v1`，API Key 填令牌。

没有设置直连提供商的令牌不能直接调用，网关会返回 503 并给出提示。请求日志里这类请求的客户端一栏显示为「直连」。

## 管理操作

| 操作 | 说明 |
| --- | --- |
| **新建令牌** | 填名称，可选直连提供商 |
| **设置** | 改名称、直连提供商与订阅账号；不会改动任何客户端配置 |
| **停用 / 启用** | 停用后，使用该令牌的客户端和直接调用都会被拒绝（403）；客户端配置不变，重新启用即恢复 |
| **重置密钥** | 生成新令牌，旧值立即失效；使用它的已启用客户端会自动改写配置。被手动改过配置（漂移）的客户端会被跳过并提示，需要在客户端页重新启用 |
| **删除令牌** | 默认令牌不能删除。删除其他令牌时，使用它的客户端会自动切换到默认令牌并改写配置；请求日志保留该令牌的名称 |

<Callout type="warn" title="令牌安全">
  令牌只对本机网关有效，与上游提供商的 API Key 无关。令牌以加密形式保存在本机，
  控制台只在你点复制时取出明文；泄露后请立即「重置密钥」。
</Callout>
