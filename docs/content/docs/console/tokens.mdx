---

令牌是访问 Astra 网关的凭据。客户端（Codex、Claude Code……）和你自己的脚本都靠令牌访问网关，每次请求的用量都记在对应令牌名下。

首次启动时 Astra 会自动生成一个**默认令牌**，启用客户端时默认写入它。需要区分用量（例如工作电脑和个人脚本）时，再新建几个令牌即可。

## 令牌卡片

每个令牌一张卡片，从上到下依次是：

- **名称与状态** — 默认令牌带「默认」徽标，停用的令牌带「已停用」徽标；
- **令牌** — 只显示前缀（如 `sk-astra-AbC123…`），点旁边的复制按钮才会取出完整令牌并写入剪贴板；
- **使用的客户端** — 当前写入了这个令牌、且已启用的客户端；
- **直连提供商** — 直接使用这个令牌调用时请求发往的提供商；配置了[提供商池](#提供商池)时显示池里的每个提供商和它当前的健康状态；
- **允许的客户端** — 这个令牌能被哪些客户端使用（见[限制客户端](#限制客户端)）；
- **最近使用** — 最后一次有请求使用它的时间；
- **限额** — 每项限额一条进度条，显示已用量、上限和重置时间；没有设置时显示「不限」；
- **今日 / 累计** 两组统计；
- **统计详情** 和 **查看日志** 两个按钮，分别打开[令牌详情](#令牌详情)和按这个令牌筛选好的请求日志。

配置了提供商池的令牌，名称旁会显示「N 个提供商 · 分配方式」和每个提供商的健康圆点。

有限额用完时，令牌名称旁会出现「已用完」徽标。

## 统计口径

| 指标 | 含义 |
| --- | --- |
| **今日消耗** | 今天（按 Astra 服务所在机器的本地日期）使用该令牌的请求费用合计，副文本为请求数 |
| **今日 Token** | 今天的输入 + 输出 token，副文本分别列出输入与输出 |
| **缓存命中率** | 缓存命中（cache read）token ÷ 输入 token；输入为 0 时显示「—」 |
| **TPS** | 加权输出速度：成功且同时测得生成耗时与输出 token 的请求，其输出 token 总量 ÷ 生成耗时总和（秒），比逐条平均更不受个别短请求影响 |
| **累计消耗 / 累计 Token / 累计请求** | 令牌从创建起的总量 |

<Callout type="info" title="累计统计不受日志保留期影响">
  「今日」统计来自请求日志；「累计」统计是独立保存的计数器，随每条请求一起累加。
  即使在设置里开启了请求日志保留天数、旧日志被清理，累计数也不会减少。
  从旧版本升级时，已有的请求日志全部计入默认令牌。
</Callout>

请求日志页可以按令牌筛选，并显示每条请求使用的令牌；筛选条件会写进地址（如 `/requests?token=<令牌 ID>`），可以收藏或分享。概览页也可以按令牌筛选，「令牌」标签页按令牌汇总费用与用量。

## 客户端如何使用令牌

在[客户端页](/docs/console/clients)启用客户端时，Astra 把 `令牌.客户端标识`（例如 `sk-astra-AbC…xyz.codex`）写进客户端配置。网关按 `.` 后面的标识识别客户端，再按该客户端绑定的提供商转发。多个客户端可以共用同一个令牌，各自的提供商互不影响。

## 直接调用

不经过客户端、直接在 curl、脚本或其他工具里使用**完整令牌**（不带 `.客户端` 后缀）也可以：

1. 点卡片上的 **设置**，在 **提供商池** 里添加提供商（订阅类提供商还可以选择具体账号）；
2. 复制令牌，把工具的 base URL 指向 `http://127.0.0.1:<端口>/v1`，API Key 填令牌。

没有设置任何提供商的令牌不能直接调用，网关会返回 503 并给出提示。请求日志里这类请求的客户端一栏显示为「直连」。

### 提供商池

只加一个提供商时，直接调用的请求都发给它，和以前的「直连提供商」完全一样。加两个或更多时，它们组成这个令牌的**提供商池**：网关按选定的分配方式挑选提供商，某个提供商限流或出错时自动换下一个。

提供商池**只作用于直接调用**。客户端通过 `令牌.客户端标识` 发来的请求仍然按[客户端页](/docs/console/clients)的绑定转发，不受池的影响。

| 分配方式 | 行为 | 适合 |
| --- | --- | --- |
| **主备**（默认） | 总是发给排在最前面的健康提供商，它失败才换下一个。拖动调整顺序 | 官方为主、中转兜底 |
| **轮询** | 每个新会话轮到下一个提供商 | 几个等价的 Key 分摊限额 |
| **加权** | 按权重比例穿插分配（平滑加权轮询，不是随机） | 灰度接入新提供商，从小权重开始 |
| **分层** | 先用第 1 层，层内按权重分配；整层都不可用时才用下一层 | 两个主力分摊，加一个备用 |
| **最少并发** | 进行中请求最少的提供商优先，响应快的自然分得更多 | 提供商速度差异大、长流式请求多 |

请求只会发给**能服务所请求模型**的提供商（提供商启用了这个模型，或通过模型映射能映射到它）。一个模型只有一个提供商能服务时，它既分不了流，也无法转移；池里没有任何提供商能服务时，请求发给第一个提供商，由上游返回错误。`/v1/models` 返回池里所有提供商模型的并集。

**同一会话固定走同一提供商**（默认开启）：同一个会话（OpenAI 的 `prompt_cache_key`、Claude Code 的会话 ID，或系统提示加首条消息的指纹）一直发给第一次服务它的提供商。上游的提示缓存不跨提供商共享，按请求轮换会让 agent 每轮都重写缓存，输入成本明显上升。会话绑定只保存在内存里，闲置 1 小时后失效；绑定的提供商冷却时会改绑到别的提供商，它恢复后已改绑的会话不会搬回去。

**失败时自动换下一个**（默认开启）只在回复开始之前进行，客户端只看到一次请求：

| 上游结果 | 换下一个 | 这个提供商之后 |
| --- | --- | --- |
| 429 限流 | 是 | 冷却到上游给出的重置时间（`Retry-After` 等响应头），最长 30 分钟 |
| 5xx、529、连接失败、连接超时 | 是 | 连续 3 次后熔断 30 秒，再失败翻倍，最长 10 分钟；到期后放一个请求试探，成功即恢复 |
| 401 / 403（API Key 型提供商） | 是 | 冷却 10 分钟 |
| 404（模型不存在） | 是 | 不冷却 |
| 400、413、422 等请求本身的问题 | 否 | 原样返回给客户端 |
| 已开始输出后出错 | 否 | 原样结束，避免客户端收到重复内容 |

每个请求最多尝试 **每个请求最多尝试的提供商数**（默认 3）个提供商。全部失败时返回最后一个提供商的错误。只有最终回答的那个提供商计费。冷却和熔断状态按提供商记录、所有令牌共享，保存在内存里，重启后清空；订阅类提供商仍按账号冷却，至少还有一个可用账号就算可用。

<Callout type="warn" title="使用提供商池前请留意">
  - 上游返回 5xx 或超时时，它可能其实已经处理了请求；换下一个提供商重试，两边都可能计费。
  - 每次连接失败最多等 30 秒，最多尝试 3 个提供商时，最坏情况要等约 90 秒才返回错误。
  - 池里的提供商在链路追踪里会显示为多次尝试，失败的那次标记为「提供商失败，换池里的下一个」。
  - 用旧版本 Astra 打开时，旧版本只认池里的第一个提供商。
</Callout>

## 令牌详情

点卡片上的 **统计详情** 打开这个令牌的详情页，可以切换今天、7 天、30 天、90 天：

- 费用、请求数、Token、缓存命中率、成功率与平均首字时间；
- 请求趋势图；
- **按提供商**：每个提供商回答的请求数、占比、成功率、平均首字时间、费用，以及「转出」（它失败、请求交给池里下一个的次数）和「转入」（它接手别人失败请求的次数）；
- **按模型**：每个模型的请求数、Token 和费用；
- 最近 10 条请求，以及跳到完整请求日志的链接。

配置了提供商池时，页面上方还会显示每个提供商的实时健康状态（正常、冷却至某时、熔断、试探中、无可用账号、已停用、已删除）。

## 限额

在令牌的 **设置** 里可以给它加限额，默认不限。每项限额由三部分组成：

| 字段 | 可选值 |
| --- | --- |
| **指标** | 费用（USD）、请求数、Token 数（输入 + 输出，输入已包含缓存命中部分） |
| **周期** | 每日、每周（周一开始）、每月（自然月）、总计（永不重置） |
| **上限** | 大于 0 的数 |

同一指标和周期只能设一次，不同组合可以同时存在，例如「每月费用 50 美元」加上「每日请求数 2000」。另外还可以设置 **每分钟请求数**（按最近 60 秒滑动计算）。

任意一项用完后，网关拒绝这个令牌的新请求，错误按客户端使用的协议格式返回：

| 情况 | 状态码 | 说明 |
| --- | --- | --- |
| 每日 / 每周 / 每月额度用完 | 429 | 带 `Retry-After`，消息里写明重置时间 |
| 总计额度用完 | 403 | 不会自动恢复，需要提高上限或删除这项限额 |
| 每分钟请求数超出 | 429 | 带 `Retry-After`，等最早的请求移出窗口即可 |

<Callout type="info" title="软限制">
  网关在请求发出前检查已经结算的用量，正在进行中的请求结束后才计入，所以并发较多时用量可能略超上限。
  被限额拒绝的请求会出现在请求日志里，但不计入任何用量统计。
</Callout>

每日、每周、每月的边界按 **设置 → 令牌额度时区** 计算，默认是服务器时区。容器里通常是 UTC，需要按本地时间重置时请改成对应时区。

## 限制客户端

**允许的客户端** 默认是「所有客户端」。改成「仅以下客户端」后，只有勾选的客户端标识（`令牌.客户端` 中 `.` 后面的部分）可以使用这个令牌，其他客户端会收到 403。一个都不勾选时，令牌只能[直接调用](#直接调用)，同时还需要设置直连提供商。

## 分享令牌与自助查询

把令牌交给别人使用时（Astra 需要监听在对方能访问的地址上，见 [Docker 部署](/docs/guide/docker)），对方可以**用令牌本身**查询它的额度和用量，不需要登录控制台：

- 打开 `http://<网关地址>/key`，输入令牌即可查看。页面分三个标签：**额度与用量**（限额进度、用量、近 30 天的每日费用）、**统计**（按时间范围的请求数、成功率、费用、首字时间、趋势、按模型和按客户端的用量、失败原因）和 **请求记录**（逐条请求，可只看失败的，向下加载更多）。令牌只保存在当前浏览器标签页里。可以把 `http://<网关地址>/key?key=<令牌>` 直接发给对方，页面打开后会立即从地址栏去掉令牌；
- 或者直接调用接口：

```bash
curl -H "Authorization: Bearer sk-astra-…" http://<网关地址>/v1/astra/key
```

返回令牌名称、允许的客户端、每项限额的已用量 / 剩余量 / 重置时间、每分钟请求数、今日 / 本周 / 本月 / 累计用量和最近 30 天的每日用量。结果**不包含任何上游信息**：没有提供商、账号、模型，也没有上游的余额或额度。

统计和请求记录也有对应的接口，同样用令牌本身鉴权：

| 接口 | 返回 |
| --- | --- |
| `GET /v1/astra/key/stats?range=today\|7d\|30d\|90d` | 汇总（请求数、成功数、成功率、费用、各类 token、平均首字时间）、时间序列（今天按小时，其余按天）、按模型和按客户端的用量、按失败原因的次数，以及请求日志保留天数。时间范围按「令牌额度时区」计算 |
| `GET /v1/astra/key/requests` | 最近的请求，新的在前；`limit`（默认 50，最多 100）、`before`（上一页的 `nextBefore`）、`status`（逗号分隔，如 `upstream_error,gateway_error`）、`model`、`client`、`from` / `to` |

每条请求只含时间、**客户端自己请求的模型名**、客户端、是否流式、结果、HTTP 状态码、失败原因分类、各类 token、费用、首字时间和总耗时。失败原因只给分类（如「上游限流」「超出令牌限额」「上游不可用」），不给原始错误信息。同样**不包含**提供商或账号的名称和 ID、实际发给上游的模型、客户端 IP、User-Agent、请求和回复内容。

拿到令牌的人能看到这个令牌的全部请求，包括同一个令牌被不同客户端使用的记录。需要分开查看时，给每个人单独建一个令牌。

很多客户端（Cherry Studio、NextChat 等）会调用 OpenAI 旧版余额接口来显示余额，Astra 也提供这两个接口，客户端可以定时查询：

| 接口 | 返回 |
| --- | --- |
| `GET /v1/dashboard/billing/subscription` | `hard_limit_usd`：最接近用完的那项费用限额的上限；没有费用限额时为 `100000000`（表示不限） |
| `GET /v1/dashboard/billing/usage` | `total_usage`：同一项限额在当前周期已用的金额，单位为美分；没有费用限额时为本月费用。请求里的 `start_date` / `end_date` 会被忽略 |

这样客户端用 `hard_limit_usd − total_usage / 100` 算出的就是真实的剩余额度。这些接口也可以不带 `/v1` 前缀访问。没带令牌或令牌无效时一律返回 401，即使设置里关闭了「网关需要令牌」也一样；已停用的令牌仍然可以查询。每个 IP 每分钟最多查询 30 次，统计和请求记录另算一份，互不占用。

额度快用完或已用完时想收到提醒，可以在[通知与 Webhook](/docs/console/notifications)里为令牌建告警规则。

## 管理操作

| 操作 | 说明 |
| --- | --- |
| **新建令牌** | 填名称，可选直连提供商（之后可在设置里扩成提供商池） |
| **设置** | 改名称、提供商池（分配方式、顺序、权重、层级、订阅账号、会话固定、失败转移）、限额、允许的客户端；不会改动任何客户端配置 |
| **停用 / 启用** | 停用后，使用该令牌的客户端和直接调用都会被拒绝（403）；客户端配置不变，重新启用即恢复 |
| **重置密钥** | 生成新令牌，旧值立即失效；使用它的已启用客户端会自动改写配置。被手动改过配置（漂移）的客户端会被跳过并提示，需要在客户端页重新启用 |
| **删除令牌** | 默认令牌不能删除。删除其他令牌时，使用它的客户端会自动切换到默认令牌并改写配置；请求日志保留该令牌的名称 |

<Callout type="warn" title="令牌安全">
  令牌只对本机网关有效，与上游提供商的 API Key 无关。令牌以加密形式保存在本机，
  控制台只在你点复制时取出明文；泄露后请立即「重置密钥」。
</Callout>
