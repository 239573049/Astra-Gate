## 外观

- **主题** — 跟随系统 / 浅色 / 深色；
- **强调色** — 跟随系统，或固定为某个系统强调色；
- **语言** — 中文 / English。语言同时决定**新请求计费说明**的显示语言。

## 开机自启动

登录系统后自动启动 Astra，macOS、Windows、Linux 都支持：

- **后台服务** — 登录后在后台启动网关，不打开任何窗口。与 `astra autostart` 是同一个开关，写入的也是同一条启动项：macOS 为 LaunchAgent（`~/Library/LaunchAgents/io.astra.server.plist`），Linux 为 systemd 用户服务（`~/.config/systemd/user/astra.service`），Windows 为注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的「Astra Server」。开关只增删启动项，下次登录才生效，不会立即启动或停止正在运行的服务；
- **桌面端**（仅桌面端显示）— 登录后在托盘 / 菜单栏中打开桌面端，不弹出窗口，服务随之启动；与托盘菜单里的「登录时启动」是同一个开关。macOS / Windows 用系统的登录项，Linux 写入 `~/.config/autostart/io.astra.desktop.desktop`。

两项都开也没关系：登录后桌面端会接管已在运行的同版本服务。几点说明：

- 只能在运行 Astra 的这台电脑上修改；
- 通过 `install.sh` / `astra update` 安装的服务端更新后，启动项会在新版本第一次启动时自动指向新版本；
- macOS 可能会在「系统设置 › 通用 › 登录项」里要求允许 Astra 在后台运行；
- Linux 需要 systemd（没有 systemd 时显示为不支持）；容器里不提供这个开关，由容器的重启策略（如 compose 的 `restart: unless-stopped`）负责。

## 网关

- **网关地址** — `http://127.0.0.1:17321/v1`（给客户端用的 base URL，可一键复制）；
- **监听** — 「仅本机」（`127.0.0.1`，默认）或「局域网」（`0.0.0.0`），详见下文；
- **数据目录** — `/Users/<you>/.astra`，可一键复制路径；
- **要求访问密钥** — 只对本机请求生效：关闭后，本机不带令牌也能用网关；局域网和远程请求始终需要令牌；
- **流式空闲超时** — 上游超过该秒数无数据则断开。
- **处理请求时阻止系统休眠** — 默认关闭。打开后，网关有请求在处理（包括流式输出）时，系统不会因闲置而睡眠，最后一个请求结束约 30 秒后解除；关闭开关或退出服务立即解除。只针对闲置睡眠：显示器照常熄灭，合盖仍会睡眠。macOS 用电源断言（与 `caffeinate -i` 相同，`pmset -g assertions` 里可以看到），Windows 用电源请求（`powercfg /requests`），Linux 用 `systemd-inhibit`（没有 systemd 时不起作用，如容器）。

### 局域网访问

把「监听」切到「局域网」，同一网络里的其他设备就能用本机 IP 访问网关和控制台：

- **必须先有管理员密码。** 还没设置时，会先弹出设置密码的对话框（至少 8 位，输入两次）；已经设置过的，会再确认一次。没有密码，服务不会在局域网上启动；
- **重启服务后生效。** 改动写入 `~/.astra/config.json`，运行中的服务不变。桌面端在开关旁给出「重启服务」按钮；浏览器里在终端执行 `astra restart`；
- 生效后，下方列出其他设备可用的**局域网地址**（每块网卡一条，可复制），以及管理员密码的修改入口；
- 本机访问（`127.0.0.1` / `localhost`）仍然免登录；其他设备打开控制台要用管理员密码登录，调用网关必须带令牌；
- 只能在运行 Astra 的这台电脑上修改；监听地址由环境变量 `ASTRA_HOST` 决定时（如容器），这里只显示、不能修改。

<Callout type="warn" title="只在可信网络开启">
  局域网内的流量是明文 HTTP，令牌和密码都可能被同一网络的设备截获。在公共网络里请保持「仅本机」，需要从外面访问时用[远程访问](/docs/guide/remote-access)。
</Callout>

<Callout title="改端口">
  在终端执行 `astra start --port <端口>`。端口被占用时 Astra 会自动顺延并把实际值写入
  `~/.astra/runtime.json`——设置页显示的永远是真实生效值。
</Callout>

## 网络代理

服务端所有出站访问——网关转发上游、订阅登录与额度、模型列表、更新检查、客户端安装（npm）——都按这里联网：

- **跟随系统**（默认）— 先用 `HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY` 环境变量（`NO_PROXY` 豁免），没有再读操作系统的代理设置；
- **自定义** — 填写代理地址（`http` / `https` / `socks5`，需带端口），可选用户名、密码与「不走代理的地址」（逗号分隔，同时匹配子域名）。保存后立即生效，无需重启；
- **不使用** — 忽略环境变量与系统代理，一律直连。

本机地址（`localhost`、`127.0.0.1`、`::1`，如 Ollama、LM Studio）始终直连；在[提供商](/docs/console/providers)里单独配置了 HTTP 代理的，以提供商为准。代理密码加密保存，接口和界面只显示「已保存」。

## 提供商用量查询

- **后台查询间隔** — 已启用「用量查询」的提供商按这个间隔（分钟）在后台刷新余额，默认 30，0 表示关闭；单个提供商可以在它的设置里另行指定。详见[提供商 → 用量查询](/docs/console/providers#用量查询)。
- **订阅账号查询间隔** — 已登录的订阅账号按这个间隔（分钟）在后台刷新额度，默认 30，最短 10，0 表示关闭。连续失败 3 次以上时间隔放大到 4 倍；失败只记录在账号上，不会改动账号状态。后台查询不会为了查额度去续期令牌：访问令牌已过期的账号会被跳过，等下一次请求续期后再查；在账户页手动刷新额度时照常续期。
- **令牌额度时区** — 令牌的每日、每周、每月限额在这个时区的零点重置，每日用量也按它统计。默认是服务器时区（容器里通常是 UTC）。详见[令牌 → 限额](/docs/console/tokens#限额)。

## 记录

- **保存请求与响应内容** — 默认关闭；打开后请求日志才能查看四个请求体（本机存储、不含密钥）；
- **在链路追踪中记录对话内容** — 默认关闭；打开后[链路追踪](/docs/console/traces#实时活动)会记下每个工具调用的参数（最多 4 KB）和用户提问、模型回复的开头（各 300 字），工具参数不经过隐私护栏；
- **内容保留** — 请求体的保留天数；
- **自动清理请求记录** — 超过保留期的记录自动删除，可设为「永久保留」或 N 天。

## 推理强度换算

OpenAI 的 `reasoning_effort`（low / medium / high）与 Anthropic / Gemini 的 thinking budget 语义不同，Astra 在协议转换时把每个档位换算成这里配置的 thinking budget（tokens）。

## 关于

服务版本、桌面端版本、更新检查与「打开日志目录」。控制台提示「服务端 API 版本与界面不一致」时，运行 `astra update` 后重启即可。
桌面端与它连接的服务版本不同时，「桌面端版本」一行会标出「与服务版本 x 不一致」；安装包版本点「立即更新」会整体更新桌面端，内置服务随之更新。

- **自动检查更新** — 服务每 12 小时检查一次发布源；
- **接收预览版更新** — 默认关闭。打开后更新检查也会提供预览版（`x.y.z-preview.N`），桌面端与 `astra update` 跟随这个设置；关闭不会降级，已装的预览版会停在当前版本，直到更新的正式版发布。详见[预览版](/docs/guide/install#预览版)。
