## 端口被占用 / 实际端口不是我配的

Astra 启动时若 17321 被占用会自动换端口，实际值写入 `~/.astra/runtime.json`：

```bash
cat ~/.astra/runtime.json
astra status        # 同样显示实际监听地址
```

脚本里请固定端口时，先确保旧进程已停止（`astra stop`），或显式指定 `astra start --port <端口>`。

## 客户端连不上网关

按顺序检查：

1. `astra status` — 服务在跑吗？
2. 控制台「客户端」页 — 客户端显示「已启用」还是「配置已被修改」？漂移说明配置被手动改回去了，重新启用或强制还原；
3. 客户端需要**重启一次**才能读到 Astra 写入的配置；
4. 若改过端口，先在客户端详情里重新「启用」或切换一次提供商，让 Astra 重写配置。

## 忘记管理密码

```bash
astra config set-password
```

重新设置即可；本机（环回）访问本来就不需要密码。

## 控制台提示「服务端 API 版本与界面不一致」

CLI、服务端与界面版本不同步（常见于手动替换过二进制）。运行：

```bash
astra update
astra restart
```

## 上游一直报错

- 提供商详情右上角 **测试连接** 看真实错误（Key 无效 / 额度不足 / 地址不对）；
- 中转站类上游注意 **价格倍率** 只影响计费展示，不影响转发；转发失败看「请求日志 → 上游错误」的错误原文；
- 需要代理的上游在提供商 **设置 → 高级 → HTTP 代理** 单独配置。

## 想彻底重置

```bash
astra stop
astra uninstall --purge   # 还原客户端 + 删除 ~/.astra
```

只想恢复客户端配置、保留其他数据时，用 `astra restore-all`（不加 `--purge`）。

## 日志在哪

```bash
astra logs -f             # 跟踪输出
ls ~/.astra/logs          # 原始文件
```

设置页的「打开日志目录」按钮直达同一位置。
