# Code map

What this is: a description of the code as of the commit above plus the uncommitted working tree (the tracing work and the
strict-JSON client repair are in the tree but not yet committed), for finding code and dependencies quickly.
When it disagrees with the code, the code wins; fix the page in the same change.
Rules live in the root AGENTS.md; reasons and history live in `.agents/memory/`.

## Flows
| Flow | Trigger | Modules | Page |
|---|---|---|---|
| Gateway request | An AI client posts a generation request | astra-gateway, astra-core, astra-data, astra-providers, astra-plugins, astra-server | [gateway-request](flows/gateway-request.md) |
| Request tracing | The same request, recorded as spans and linked into its agent's turn | astra-gateway, astra-core, astra-data, astra-server, web-ui, docs-site | [request-tracing](flows/request-tracing.md) |
| Privacy redaction | Any client request with the guard enabled | astra-gateway, astra-core, astra-server, astra-data, web-ui, astra-plugins | [privacy-redaction](flows/privacy-redaction.md) |
| Token limits enforcement | A request with a limited gateway token | astra-gateway, astra-core, astra-data, astra-server, web-ui | [token-limits-enforcement](flows/token-limits-enforcement.md) |
| Client config take-over | Enable/disable/restore a local AI client in the console or the CLI | web-ui, astra-server, astra-clients, astra-data, cli | [client-config-takeover](flows/client-config-takeover.md) |
| Plugin install and run | Install a plugin from the market/git/npm, then a matching request | web-ui, astra-server, astra-plugins, astra-gateway, astra-clients, astra-data | [plugin-install-and-run](flows/plugin-install-and-run.md) |
| Admin API request | The console or CLI calls `/api/**` | web-ui, cli, astra-server, astra-data, astra-core, desktop-app | [admin-api-request](flows/admin-api-request.md) |
| Server startup | The CLI, desktop, a container or a user starts `astra-server` | astra-server, cli, desktop-app, astra-data | [server-startup](flows/server-startup.md) |
| Provider quota refresh | The quota worker's interval, or a manual check | astra-server, astra-providers, astra-data, astra-core, web-ui | [provider-quota-refresh](flows/provider-quota-refresh.md) |
| Subscription account refresh | A subscription account comes due, or a manual refresh/import | astra-providers, astra-server, astra-data, astra-core, astra-gateway, web-ui | [subscription-account-refresh](flows/subscription-account-refresh.md) |
| Release and update | A version bump lands on `main`; later, an installed client updates | packaging-release, astra-server, cli, desktop-app, update-core, docs-site | [release-and-update](flows/release-and-update.md) |

## Not yet mapped
- `tests/**` — the xunit projects are described inside each module page (where the fixtures live, how to run one
  project), but there is no page of its own: there is no separate test infrastructure beyond `TestDb` / `TestHome` /
  `VanillaDapper` and the gateway fixture tree.
- `.plan/*.md` and `.plan/prototypes/` — local, gitignored planning documents. Code comments cite them as "plan §N".
  They are inputs to a change, not code, and they are not committed, so they are deliberately not mapped; the
  memory entries record the decisions that outlived them.
- `src/Astra.Server/Properties/`, `appsettings.json`, `Directory.Build.props`, `.prettierrc`, `eslint.config.js` —
  build/formatting configuration, covered by the root AGENTS.md conventions section rather than by a map page.
