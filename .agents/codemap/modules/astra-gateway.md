# astra-gateway

The inbound HTTP surface for AI clients: `GatewayPipeline.HandleAsync` authenticates the presented
Astra token, routes to a provider (and possibly a subscription account), redacts through the privacy
guard, then either passes the client's bytes through or converts them through the hub-and-spoke IR —
streaming the answer back while recording timing, usage and cost on one `RequestRecord`.
**Not responsible for:** the host, DI wiring and every `Map*Endpoints` call (`astra-server` —
`AstraApp.Create`), domain types, settings/app-settings, pricing/billing math and the privacy
detector itself (`astra-core`), SQLite repositories and migrations (`astra-data`), provider
templates, subscription token/refresh internals and quota polling (`astra-providers`), the Jint
runtime, plugin catalogue and Bun host (`astra-plugins` — this module only *calls* them), client
config rewriting and install (`astra-clients`), and the UI/CLI/Docker side (`cli`, `web-ui`,
`desktop-app`, `docs-site`, `update-core`, `packaging-release`).

## How to extend
- To add a wire protocol: implement `IProtocolCodec` (a stateless singleton plus per-response decoder/encoder) and register it in `GatewayCodecs.Register` (`src/Astra.Gateway/Protocol/GatewayCodecs.cs:8`), then add its routes in `MapGatewayEndpoints` and, if the protocol carries the model in the URL, thread `pathModel`/`pathStream`/`pathAltSse` like Gemini (`src/Astra.Gateway/Pipeline/GatewayPipeline.cs:62`). Missing the registration makes the registry return null and a converted request fail with a 501 "no conversion" (`GatewayPipeline.cs:196`), while a missing route is just a 404.
- To add a route: add the `MapPost/MapGet` lambda in `GatewayEndpoints.MapGatewayEndpoints` (`:18`) and note that `SecurityMiddleware` deliberately leaves `/v1`, `/v1beta` and the key-info paths alone — they authenticate with tokens, not sessions (`src/Astra.Server/Security/Security.cs:81`).
- To add a pipeline stage: insert it into `HandleAsync`'s `try` in the place that matches its inputs, and register the type in `AstraApp.Create` (`src/Astra.Server/Hosting/AstraApp.cs:91`–`:113`). Stages are ordered deliberately: route → `TokenLimiter` → body read → middleware → link (`TraceKeys`/`TraceLinker`, read from the client's own body) → privacy guard → model/endpoint → sticky key & body rewrites → send → stream/buffer/collapse → `Finish` → `FinishTrace` → `UsageWriter.EnqueueAsync`. Putting a stage after the body parse loses the client's original bytes (`bodyIsClientBytes`, `GatewayPipeline.cs:201`); putting one after `SendAsync` cannot prevent the request from leaving the machine. A stage that should show up in the trace views needs its own span (see [request-tracing](../flows/request-tracing.md)) — a timer nobody reads is invisible.
- To add a lossy mapping: record it with `request.Warnings.Add(...)` at the decode/encode site (`src/Astra.Gateway/Protocol/Gemini/GeminiRequests.cs:179`, `ResponsesCodec.cs:383`) and document it in the owning codec's class comment (the `ResponsesCodec` header at `src/Astra.Gateway/Protocol/Responses/ResponsesCodec.cs:11` is the model) and in the `Ir.cs` comment on the type that loses the information (`Ir.cs:42`, `:121`, `:208`). Warnings are logged once per request (`GatewayPipeline.cs:272`) — an undocumented drop is invisible.
- To add a debug body part: a new `BodyStore` constant (`src/Astra.Gateway/Pipeline/BodyStore.cs:14`–`:19`), a `capture?.Set(...)` call, and the reader side in `astra-server`'s request-detail endpoint; missing the reader side writes a file nobody can open.
- To add a per-request observable for the UI: set a field on `RequestRecord` and call `live.Update(record)` (the feed coalesces per request and only records while a viewer is subscribed — `LiveRequestFeed.cs:88`), and add the field to the request-log DTO in `astra-server`.
- To add a smart-routing judge dialect: implement `IRoutingJudge` in `src/Astra.Gateway/Routing/` (build the request and read the answer with `JsonNode`, post through `JudgeHttp.PostAsync` — never `GatewayHttpClients.For` directly: the judge's own client keeps its connection warm, and a cold connection costs more than a judgement's deadline — finish with `JudgeParsing.Verdict` so an unknown grade or a missing confidence is a `BadResponse`), register it in `RoutingJudges.Register`, add its `JudgeProtocols` constant, and cover it with golden fixtures in `tests/Astra.Gateway.Tests/Fixtures/routing`; the console side is the `PRESETS` and `smartRouting.judge.protocol.<id>` keys in `web/src/components/SmartRoutingSettings.tsx`.

## Invariants and traps
- **Nothing leaves the machine before the privacy guard runs**, and the guard runs on the client's own body *before* any codec derives upstream budgets from it — a block is answered as a 400 in the inbound protocol's shape (`GatewayPipeline.cs:137`, `:146`). The order middleware → privacy is deliberate: middleware see the agent's body in its own API, and whatever they send on is still guarded (`GatewayPipeline.cs:116`).
- **The pass-through fast path is literal**: when nothing rewrote the body and the guard changed nothing, upstream gets the client's own bytes (`bodyIsClientBytes`, `GatewayPipeline.cs:151`, `:319`); the *response* is forwarded byte by byte while being parsed only to observe usage/TTFT/errors (`forwardBytes`, `:753`) — except a GitHub Copilot Responses stream, whose per-event item ids are pinned per `output_index` first (`Protocol/Responses/ResponsesItemIds.cs`; otherwise Codex shows each message twice). Any stage that rewrites the tree sets `upstreamDirty` and forces a re-serialize.
- On the byte-forward path an upstream that declared `text/event-stream` is not held until its first event: comment
  lines (heartbeats while the model thinks) reach the client at once, so idle-timing proxies keep the connection
  (`forwardDeclaredSse`, `GatewayPipeline.StreamAsync`). A JSON body under that content type is forwarded as it comes.
- A remote request (tunnel / Cloudflare proxy) always needs a token, whatever `RequireGatewayKey` says — the switch only opens the gateway to this machine (`GatewayRouter.cs:68`, `RequestOrigin.cs:6`).
- `GatewayException`/`ProtocolException` messages are written in **Chinese** (client-facing), matching the surrounding code (`GatewayPipeline.cs:146`, `:197`); log-only text stays English. `RecordErrorType` overrides what the log stores, so a 429 from a token limit is recorded as `TokenLimits.RefusedErrorType`, not `rate_limit_error` (`TokenLimiter.cs:59`).
- `TokenLimiter` is *soft*: it reads settled usage, so requests already in flight can push a budget past its limit (`src/Astra.Gateway/Pipeline/TokenLimiter.cs:9`). The ledger counts a request the moment it is queued for writing, so the DB alone lags a burst (`TokenUsageLedger.cs:38`); a request persisted exactly while its token loads may be counted twice or not at all.
- An `AccountScheduler.Lease` must always be disposed (the pipeline's `finally`, `GatewayPipeline.cs:446`) and `SendAsync` releases it itself when the send throws (`:585`) — a leaked lease leaves the account permanently over-counted in flight.
- `PooledBuffer` is reference-counted: the pipeline releases its reference in `finally` (`GatewayPipeline.cs:455`) while a still-running send holds its own through `PooledContent` (`RequestBody.cs:127`). Reading a `RequestBody` tree after `Dispose` is a use-after-return.
- The account's own proxy beats the provider's, and a 401 retry reuses that exit for the same account (`GatewayPipeline.cs:520`) — a proxy must be picked from the credentials, never from the provider, once an account is chosen.
- `UpstreamAuth.CanRefresh` allows **one** `ResolveAfterUnauthorizedAsync` renewal after 401/403 (a plugin reloads its
  sign-in instead); direct tokens and API keys skip it. A still-rejected account cools for 10 min in failover/balanced
  mode, even after renewal succeeded, and the request moves to an untried account (`auth_failover`). Resolution
  failures also hand over; manual mode preserves upstream auth errors. A channel rejection alone does not revoke a
  grant, and a direct token's usable lifetime is its actual expiry rather than the renewal lead.
- Endpoint selection honours a per-model protocol constraint: `SelectEndpoint(provider, inbound, supportedProtocols)` never falls back to a protocol the model does not support — it throws a 503 naming the protocols instead (`GatewayRouter.cs:174`).
- `force_stream` (ChatGPT/Codex) pins the upstream to `stream: true`, `store: false`, array `input`, and strips `CodexUnsupportedParams` (a 400 "Unsupported parameter" otherwise); a client asking for non-stream then gets the whole SSE collapsed into one JSON body (`GatewayPipeline.cs:55`, `:274`, `:348`, `CollapseStreamAsync` at `:1022`).
- Header and body must agree on a Claude subscription: the Relay path merges the OAuth `anthropic-beta` **and** promotes `cache_control` ttls (`ClaudeOAuthHeaders.MergeRelayBeta` / `PromoteCacheControlTtl`); only one of the two is "claiming subscription identity while shipping an API-key-shaped body" and the upstream answers 403 (`GatewayPipeline.cs:301`, `ClaudeOAuthHeaders.cs:77`). The User-Agent must be a single product token — the CLI's `claude-cli/x.y.z (external, cli)` cannot be represented by `ProductInfoHeaderValue` and would be re-emitted with a comma, which the upstream reads as a non-CLI client (`ClaudeOAuthHeaders.cs:226`).
- For OpenAI Chat streaming, Astra injects `stream_options.include_usage` when the client did not ask for usage and then **filters that usage-only chunk out** of the client stream (`GatewayPipeline.cs:250`, `IsChatUsageOnlyChunk` at `:1236`) — forgetting the filter leaks an extra chunk the client never asked for.
- Gemini carries the model and the stream flag in the URL, never the body: `StripModels` removes the `models/` prefix everywhere a model is taken from the path (`GatewayPipeline.cs:1261`), and `:streamGenerateContent` without `?alt=sse` answers with a JSON array, not SSE (`JsonArrayBody`, `GatewayPipeline.cs:365`).
- `RequestBody.ReadAsync` caps the body at 64 MiB (`GatewayPipeline.MaxRequestBytes`) **after** decompression and rejects an unknown `Content-Encoding` with a 415 (`RequestBody.cs:243`, `:277`).
- `IdleTimeoutReader` re-arms one token source per read and floors the timeout at 5 s; a stream that stalls becomes a 504 (or an error event when Astra encodes the stream) rather than an infinite wait (`GatewayPipeline.cs:1199`, `:803`).
- `MiddlewareResponseStream` must be completed once the pipeline is done (the pipeline's `finally`, `GatewayPipeline.cs:433`) and it decides its mode from the headers at the first write — a whole JSON reply is buffered until then, and a compressed body passes as-is (`MiddlewareResponseStream.cs:122`).
- The gateway's JSON output is `JsonNode`-based, not typed DTOs, so the AOT `JsonContexts` registration rule mostly does not apply here — the exception is `RequestBilling`, which serializes `List<BillingTraceStep>` and `List<string>` through `JsonContexts.Info<T>` (`RequestBilling.cs:45`, `:57`).
- `GatewayHttpClients` disables the Activity header propagator on purpose: the default would copy the agent's traceparent and baggage into the provider request (`Upstream.cs:97`), and it sets no overall timeout — timeouts belong to the connect (30 s) and per-read idle settings. The inbound `traceparent` is only ever the parent of the root span (`GatewayPipeline.cs:93`).
- `TraceLinker` is process-wide and in-memory (`TraceLinker.cs:TraceLinker`): it links by tool-call id first, then by session, and guesses a sub-agent or side call from a different chain fingerprint. A restart, or an id evicted past `MaxToolCalls`, falls back to `link_source = session` — the views must not treat every link as exact.
- Account selection is skipped entirely for non-account auth schemes; only `OAuthSubscription` (and plugin) providers get failover/balancing (`GatewayPipeline.cs:475`, `:480`).
- Smart routing's judge call is the one request the gateway makes on its own, and it happens **after** the privacy guard (right after the `gateway.resolve` span opens), reading the guarded body — so the "nothing leaves before the guard" rule still holds. It never fails the user's request (`SmartRouter` turns every judge failure into the fallback grade), it is detached from the request's cancellation (a flight is shared by concurrent first requests of a session), and its pins and turn cache live in memory only: a restart forgets them. `TraceLink.SessionKey` is not token-scoped; `SmartRouter` prefixes the token id. A side call (`CallKind == aux`) is judged on its own and never pins the session; a sub-agent shares the main turn's decision.
