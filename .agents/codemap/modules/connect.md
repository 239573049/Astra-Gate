# connect (npm `@aidotnet/astra-connect`, bin `astra-connect`) + client-config

The employee side of an enterprise deployment: a company runs Astra Server, hands each employee an API key (an Astra
token), and the employee runs `astra-connect join <gateway>` to point the local AI clients at it — with backups and a
drift-aware restore (`leave`). Pure TypeScript, no server binary; clients talk to the company gateway directly.
`connect` is the CLI (commander + `@clack/prompts`); `packages/client-config` (source-only, bundled by tsup) is the port
of `src/Astra.Clients` it runs. Design and decisions: `.plan/enterprise-connect.md`.
**Not responsible for:** the gateway (`astra-gateway`), the local-server client take-over (`astra-clients`, which this
mirrors), anything about providers/accounts.

## Entry points
| Symbol | File | Role |
|---|---|---|
| commander root | `connect/src/index.ts` | `join` / `status` / `leave` / `doctor`; picks `clackUi` (TTY), `plainUi` (scripts) or `silentUi` (`--json`). |
| `join` | `connect/src/commands/join.ts` | Key (env / stdin / masked prompt) → `GET /v1/astra/key` → `GET /v1/astra/connect-context` → clients → model → plan preview → `applier.apply` → `profile.json`. |
| `leave` / `status` / `doctor` | `connect/src/commands/*.ts` | `applier.disable` / `forceRestore`; limits + per-client `inspect()`; connectivity + drift + repairs. |
| `buildContext` / `defaultModelFor` | `connect/src/lib/clients.ts` | The `EnableContext` per client kind (ClientService.ContextAsync's shapes, with the bare token) and the per-family default model. |
| gateway client | `connect/src/lib/gateway.ts` | `normalizeGatewayUrl`, `fetchKeyInfo`, `fetchConnectContext`, error kinds. |
| profile | `connect/src/lib/profile.ts` | `~/.astra/connect/{profile.json (0600), state.json, backups/}`; `localAstraRuns` reads `runtime.json`. |
| `ClientConfigApplier` | `packages/client-config/src/applier.ts` | Port of the C# applier: first-write + 20 rolling backups, per-key state, drift-aware restore, `reconcileToOriginal`. |
| editors | `packages/client-config/src/editing/*` | `JsoncEditor`, `TomlEditor` (toml-eslint-parser locates, text splices edit), `YamlEditor`, `DotEnvEditor`, `ShellBlockEditor`, `DiffTool`, `StrictJson`. |
| `ClientAdapterBase` + adapters | `packages/client-config/src/adapter-base.ts`, `adapters/*.ts` | The 28 built-in adapters; `adapters/group-N.ts` + `claude-code.ts` feed `ClientAdapterRegistry.createDefault`. |
| `JsonFileStateStore` | `packages/client-config/src/state.ts` | `client_config_state` as a JSON file (Node 18 has no SQLite). |

## Contracts
- Same bytes as C#: `tests/fixtures/client-config/<kind>/<case>/` run by `GoldenClientConfigTests` (C#) and
  `packages/client-config/test/golden.test.ts` (TS); `expected/` is generated by the C# side only.
- Server: `GET /v1/astra/connect-context` (`KeyInfoEndpoints`) — token name + callable models; 401 without a valid key even
  when `RequireGatewayKey` is off.
- The key is never an argv value; the clients get the bare token.

## Extension steps
- New client: C# adapter first (see astra-clients), then `packages/client-config/src/adapters/<kebab>.ts`, one line in a `group-N.ts`,
  cases under `tests/fixtures/client-config/<kind>/`, regenerate `expected/` with the C# test.
- New command: `connect/src/commands/<name>.ts` taking `(rt, ui, io, …)`, wired in `index.ts`, tested over `test/helpers.ts` (fake gateway + fake home).
